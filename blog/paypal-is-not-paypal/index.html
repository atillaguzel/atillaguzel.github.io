pаypal is not paypal

18 November 2026

It is late, and somebody is filling in a sign-up form. They type a name that is already taken. The form thinks for a moment and lets them in.

username pаypal available

Now come back to this page and look at its title, because the same thing has just happened to you. The second letter of the first word is a stranger. I'll show you.

pаypal is not paypal The second letter is U+0430, the Cyrillic small letter a.

Most typefaces draw that letter exactly like the Latin a. A database sees two different names. You and I see the same name twice. I maintain confusable, a Python library for this problem, and this is the short version of how the visitor got in and how to keep the next one out.

How the visitor got in

The form had one rule: no two accounts may share a name. It checked the new name against every name it held, found no match and opened the door. The rule did its job. The trouble is what counts as the same name, and there are three ways to make one that only reads like another.

  • A letter from another alphabet. Cyrillic and Greek each have letters that are drawn like Latin ones: а, е, о, р, с and more.
  • A look-alike from the same alphabet. rn beside m, a capital I beside a small l, the digit 1 beside either.
  • A character you cannot see. A zero-width space inside pay​pal changes the name and leaves nothing on screen. A right-to-left override makes a file called invoice[U+202E]gpj.exe display as invoiceexe.jpg.

Protected here: paypal, admin, support, microsoft. This is a small in-browser check that knows about twenty look-alikes. The library carries the full Unicode table.

What the form should have compared

Back to our visitor. This time the site does one extra thing before it answers. It rewrites the name in the plainest letters it can, so each look-alike turns into the letter it was imitating. That plain version is called a skeleton, and it comes from Unicode Technical Standard #39. Two names are confusable when their skeletons are equal.

the visitorpаypal the real onepaypal same skeleton

You can do the same in a few lines of Python.

import confusable

confusable.skeleton("pаypal")   # 'paypal'
confusable.skeleton("microsoft")     # 'rnicrosoft'
confusable.skeleton("rnicrosoft")    # 'rnicrosoft'

The second result looks wrong at first. A skeleton is not a tidied-up name. It is a key for comparing, and the standard happens to pick rn as the plain form of m. So the site stores the skeleton beside the name and applies its one rule to that.

def username_keys(name: str) -> tuple[str, str]:
    """Return the keys that must each be unique among usernames."""
    return (
        confusable.skeleton(name),
        confusable.skeleton(name.casefold()),
    )

There are two keys because a skeleton keeps case: you can tell Paypal from paypal, so it does too. Most sites treat usernames as the same whatever their case, and the second key folds case first. That is the one PAYPA1 and paypal share.

Not every name is a username

One caution before you add this to every text box you own. The checks that suit a username would turn away a great many real names.

TextHold it toRefuse
Usernames, handles, slugsA strict set of letters, digits and a little punctuationScripts that are not used together, mixed digit systems, a skeleton that is already taken
Display namesNothing: spaces, emoji and mixed scripts are how people write their namesInvisible characters, piled-up accents, a skeleton that matches a name you protect
FilenamesThe file system's own rulesInvisible characters, and an extension that reads differently from what it is

The standard defines each check and leaves the policy to you. The library's guide on accepting names safely has a starting recipe for each row, and that code runs in the test suite.

two cautions

confusable is in alpha, so names and signatures may still change. And skeletons change when the Unicode data does. Store the Unicode version beside them and recompute when it moves.
